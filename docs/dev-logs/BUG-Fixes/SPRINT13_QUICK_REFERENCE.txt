WHAT WAS FIXED
═════════════════════════════════════════════════════════════════════════════

1. USER-AGENT ROTATION (✅ NOW WORKING)
   Problem:  All requests in a session used the same User-Agent
   Cause:    rand.Seed(time.Now().UnixNano()) was resetting RNG every call
   Fix:      Removed rand.Seed() from ApplyEvasion()
   Result:   Each request now gets different random User-Agent
   File:     pkg/logic/evasion.go (line ~82-98)

2. TLS EVASION (⏳ DEFERRED TO SPRINT 14)
   Problem:  Static TLS profile broke all discovery functions
   Cause:    Forcing fixed TLS fingerprint breaks server compatibility
   Fix:      Disabled ApplyTLSEvasion() call in InitializeRotaryClient()
   Result:   All discovery modules restored and working
   File:     pkg/logic/network.go (line ~282-285)

ARCHITECTURE NOTES (FOR SPRINT 14)
═════════════════════════════════════════════════════════════════════════════

Per-Request TLS Evasion (Next Sprint):
  Challenge: Go's http.Transport reuses TLS connections
  Solution:  Need custom DialTLSContext that reads profile from request context
  
  Flow:
    1. RoundTrip() calls ApplyPerRequestTLSEvasion()
    2. Returns TLS config for this request
    3. Store in request context (via context.WithValue)
    4. Custom DialTLSContext reads from context
    5. Each connection uses appropriate profile
  
  Benefits:
    ✓ True per-request TLS rotation
    ✓ Varies JA3 fingerprints
    ✓ Defeats TLS-based detection
